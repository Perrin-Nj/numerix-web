# Backend requirements (owned by the frontend work)

Single list of everything the frontend needs from the backend. `openapi.yaml` and `openapi.admin.yaml` are the machine-readable contract, `BACKEND_INTEGRATION.md` explains the behaviour, and this file tracks the why, the owner, the priority and the test. Update it in the same pull request as the frontend change that creates the need (see `docs/frontend-spec.md` section 22.6). `bash scripts/test.sh contract` fails when a row below lacks an owner, a priority, a test or a valid guide link.

Status values: `proposed` (not in the OpenAPI files yet), `in-contract` (in the files, not built), `built`, `verified` (checked against the live backend).

Priority: **P0** blocks launch, **P1** soon after launch, **P2** later. Test ids `AC-nn` are the rows of section 27 of the guide ("Acceptance checklist").

## BE-22: card threshold (admin dashboard)

A chapter awards its card only when correct answers / answered beats >= `card_threshold_pct` (default 70). The value is a setting owned by the admin dashboard (`PlatformConfig.card_threshold_pct`), readable by the engine per deployment, and returned on the session as `score { correct, total, pct, threshold_pct, card_awarded }`.
